# 通用项目开发规范 V1.2

适用范围：游戏、应用、网站及其他软件项目。配合独立的玩法或产品文档使用；本规范约束开发方式，不替项目决定题材、引擎、平台、语言或商业模式。

### 新会话启动提示词

请将本规范作为本项目的开发与验收基线，将我附上的玩法／产品文档作为产品需求来源。首次完整开工核验规范版本、commit和适用流程，续接只核验变化；需要3D时执行可选资产流程。先读取现有资料、代码和交付记录，核实环境与权限，不要凭历史印象假定工作已完成。请输出项目参数、MVP范围、不做清单、关键假设、风险、阶段计划、角色分工和首个可验证里程碑；只对阻塞推进的缺项提问，其他可逆假设写明后推进。

先做限时限费的探索，机制／任务原型与目标设备、SDK及美术技术风险试验可并行。需要验证手感时提前制作小规模音画样例。通过代表性垂直切片验证体验与生产成本后，再批准大规模架构、资产和内容生产。素材未齐时使用占位；每阶段按证据继续、改向或停止，不以堆功能替代验收。

按模块划分代码、数据、表现与外部服务，明确文件归属、接口、分支和集成负责人。优先审计与复用成熟组件，不默认所有旧代码或跨引擎素材都能直接使用。实现人员按已批准的视觉规范还原，不自行重设计。独立测试覆盖逻辑、界面、目标设备和真实用户体验；工具测试不可冒充真人试玩，模拟数据不可冒充线上服务。

主动推进已授权范围内的工作，关键决策与范围变化提交确认。阶段结束提交可运行版本、验收证据、版本定位和风险清单；严格区分已编写、已测试、已提交、已推送、已部署、目标设备已运行和已发布。密钥不得进入代码、日志或交付包。未经验收不得宣称完成。

### 使用方法

每个新项目附上本规范与项目文档即可启动。项目文档不齐时先建立输入清单，不重写一套流程；后续变更进入决策记录。默认采用个人＋AI轻量模式，角色是责任而非六个常驻会话。小项目可一人兼任，但重要变更应由另一轮独立检查或另一位评审者验证。

阅读导航：按下方章节阅读；可选3D完整流程见 [OPTIONAL_3D_PIPELINE.md](OPTIONAL_3D_PIPELINE.md)。

## 01 项目输入与范围基线

### 启动前必须确认的项目参数

| 字段 | 必须写清的内容 |
| --- | --- |
| 产品与用户 | 产品目标、目标人群、核心场景、要解决的问题或核心体验。 |
| 范围与商业 | MVP闭环、不做清单、预算与时间约束；是否含广告、支付、账号、排行榜等。 |
| 技术与设备 | 目标平台、最低支持设备、输入方式、横竖屏、在线／离线需求、已有仓库和环境。 |
| 体验与内容 | 核心规则、主流程、失败／成功条件、内容规模、语言与可访问性要求。 |
| 交付与权责 | 项目负责人、验收人、运行及发布目标、资产授权范围、代码与素材归属。 |
| 验证与风险 | 核心假设、验证方法、通过阈值、停止／改向条件、未决事项及截止点。 |

### 先恢复事实 再制定计划

盘点现有文档、源代码、资产、存档、分支、提交和实际可运行状态。记录“已验证事实／待验证假设／阻塞项”，不得将聊天中的计划当成完成记录。无法访问的附件或设备明确列出，不凭空补齐。

### 范围与成功标准

• MVP交付须有完整核心闭环及必要的失败、恢复和退出路径；探索原型可以只回答一个问题并被丢弃，不要求生产级恢复。把可延后内容列为不做清单，不能默默加入。

• 成功标准包含可量化技术指标和体验目标。指标由项目设定，例如首次任务完成率、响应时间、崩溃率、真人愿意再玩／再用的证据；样本量与测试条件必须一起记录。

• 每轮探索写明问题、时间／费用上限、继续／改向／停止证据。预算到期必须决策，不无限返工。商业化另列获客、服务和制作成本与收益假设，广告不保证赚钱；一次演示不等于市场验证。

### 变更与决策优先级

最新明确批准的决策优先于旧版本项目文档。发现冲突先标记影响并取得决策，不静默混用。改变核心玩法、主要视觉、架构、外部费用、权限或发布范围需确认；范围内可逆缺陷修复可直接推进并留记录。每次批准后更新唯一基线与版本号。

### 项目输入短模板

一句话卖点：____。核心一分钟：用户做____，收到____反馈，再决定____。最小样例：先把一个____做通；观察到____才扩展。明确不做：____。关键边界／例外：____。验收人及批准基线：____。

## 02 责任分工与轻量协作

| 角色 | 职责与交付 | 边界 |
| --- | --- | --- |
| 总控与集成 | 维护范围、计划、依赖、版本；分配文件归属；审核闸门并组织集成。 | 不以口头完成替代证据。 |
| 产品与体验 | 核心规则、主流程、竞品证据、数值／内容设计、真人反馈与决策。 | 不以自动求解证明好玩。 |
| 架构与核心研发 | 模块接口、业务状态、存档、服务适配、测试与性能。 | 不自行修改产品规则。 |
| 美术与 UI | 效果图、交互规格、组件与全状态资产、动画和音效规范。 | 确认后再批量制作。 |
| 界面与表现实现 | 按规格拼装、接数据与事件、响应式适配、动画播放。 | 不替代设计擅改美术。 |
| 独立 QA | 设计用例、操作实际构建、复现缺陷、回归并出具结论。 | 不能仅引用作者自测结果。 |

### 并行工作必须先有契约

• 只为有实际协作风险的任务记录输入、产出、负责人、验收人、依赖与完成条件，不为简单修改新建一套表单。文件或模块只有一位当前写入负责人；共享场景、工程配置和入口文件由集成负责人维护。

• 接口按真实复杂度说明数据与调用边界。同步简单模块不强写异步契约；存在异步或外部服务时再明确错误、取消与重试语义。需要变更先通知依赖方，提供迁移方案，不在主线临时改名。

• 并行或有冲突风险的任务使用独立分支／隔离目录；单人顺序微小修改可在同一受控分支小批提交，关联需求与缺陷编号。合并前运行约定检查，由集成负责人解决冲突并验证主线仍能运行。

### 建议并行顺序

探索期并行验证核心机制、任务效率与高风险技术／美术环节。批准关键体验后，用最小架构和样例资产做代表性切片；切片证明体验、性能和制作产能后才扩量。接口按需要明确，资产逐批进入，测试同步进行。

### 沟通与交接

以仓库中的需求、接口、资产清单、缺陷表和验收报告为共同依据。每个阶段汇报“完成了什么、证据在哪里、剩余风险、下一步”；阻塞和影响范围立即报告。模型与工具选择服从任务和权限，实际使用情况写入交接，不以模型名称代替质量验收。

## 03 探索与预生产闸门

### G0 探索立项 Discovery

交付：项目目标、MVP与不做清单、最高风险假设、探索预算与决策日期、责任与证据位置。提前识别平台发布、隐私、儿童、付费及签名约束。通过：问题、验证方法和继续／停止条件明确。失败处理：补关键输入、缩范围或停止。以下阶段名是本规范约定。G1至G3可重叠迭代，编号不要求先完成全部视觉再验证技术。

### G1 并行原型 Prototype

交付：真实竞品记录、针对问题的可运行原型、观察结果与未验证项。机制／体验原型可与目标设备、SDK、3D或渲染风险小样并行；音画影响手感时可早做。原型可丢弃，不必实现完整生产系统。竞品注明来源、日期、观察与推断，广告不等于实际产品。

通过：原型回答预定问题并达到项目阈值。游戏验证操作、反馈和选择；工具验证任务完成、效率与错误恢复。小样本用于发现问题，不证明留存或市场成功；不要求每个原型都包含整个闭环。未决高风险须有下一步试验。

失败处理：在剩余预算内调整并复测；到决策日期必须继续、改向或停止，延期需重新批准预算。不能靠堆内容或特效掩盖核心缺陷。

### G2 流程与视觉基线

交付：信息架构、主流程与异常流程、关键页面效果图、视觉组件表、目标分辨率及适配方案、关键动效小样。所有可交互元素都标注动作与结果。

通过：确认关键流程与视觉基线，在目标尺寸检查层级、热区、可读性和动效响应。输入反馈、加载、帧时间、内存、持续运行温升及文字／颜色／输入适配预算由项目填写，不设统一阈值。真实设备暴露的问题可提出批准变更；像素还原不能高于可用性。

失败处理：修改关键页面或流程，不先生产整套切图。局部修订采用差异说明；核心布局变化需重新确认受影响页面。

### G3 最小架构与构建链

交付：支撑切片的最小模块边界、数据／存档方案、占位主流程及可重复执行的构建脚本。固定commit、依赖、工具链和配置，构建产物记录校验值。通过：可按说明重建和启动，测试绑定实际构建包。CI按规模采用，不要求所有构建字节级完全相同。失败则先修依赖或状态。

阶段签字只代表该闸门通过。未经记录的未验证项继续保留，不自动转为已完成。

## 04 切片生产与发布闸门

### G4 代表性切片 Vertical Slice

交付：正式视觉与核心逻辑结合的一段完整体验。游戏示例为进入、引导、游玩、失败／恢复、胜利、结算、下一局；其他产品对应首次进入、核心任务、保存／提交、结果和再次使用。按项目裁剪，不强加无关系统。

切片仍属预生产，选能代表典型内容与主要风险的样例，不只选最简单场景。通过：真实构建端到端走通，目标设备达标；记录每单位内容生产时间、返工成本与产能，验证预算可承受。负责人批准后才进入生产；失败则在预算内修正或改向，不扩量。

### G5 生产 Alpha 与 Beta

本规范约定Alpha为计划功能齐全、Beta为计划内容齐全。Alpha后不默认增加核心功能；Beta后原则上只修复、平衡与准备发布，新增范围须评估成本并批准。交付：逐批验收的功能、资产与内容。通过：结构稳定、数据合法，每批可运行回归且符合产能预算。内容QA自动检查资源引用、ID和参数，结合代表性／极端样例人工抽测，不宣称每关都由真人完整测试。

游戏关卡专项应同时检查可解性、解法空间、贪心／乱点策略成功率、重玩差异和真人感受。不能把高步数、唯一解或自动求解耗时等同于玩家难度。按新手、有同类经验和熟练用户的实际测试结果调节；不可伪造模拟人群结论。

失败处理：回滚问题批次或修复生成规则后重测。优先修共同根因，不逐关手工掩盖同一缺陷。

### G6 固定发布候选 RC

交付：冻结候选包及其校验值、源commit、工具链与配置、分层报告、设备证据、隐私授权清单和恢复方案。通过：关键路径和回归通过，无未处理的阻断／严重缺陷，剩余风险由负责人明确接受；离线、恢复、升级迁移与外部服务异常均有证据。

失败处理：修复后生成新的候选版本并重跑受影响回归。不得用上一版测试报告为新版背书，也不得仅因期限到达就自动放行。

### G7 交付与上线观察

交付：可定位源代码、构建产物、部署／安装指南、版本说明、测试证据、维护负责人和监测方案。通过：接手者能按文档在指定环境运行；需要发布的项目已核实发布结果。若仅交付本地版本，明确截止于本地验收，不称为上线。

发布前验证必要日志与事件及版本标记；上线后按约定窗口检查崩溃、性能、任务完成及适用商业指标。事故时区分停止扩量、发布修复、远程功能关闭、服务端回滚和存档恢复；商店暂停分发不能撤回已安装版本。阈值触发明确责任人与动作，没有数据不编造结论。

## 05 按复杂度组织架构

| 层级 | 负责什么 | 不得承担什么 |
| --- | --- | --- |
| 核心领域 | 规则、计算、合法性、状态转换；尽量纯逻辑、可测试。 | 直接操作界面、SDK或资源路径。 |
| 应用服务 | 用例编排、会话、保存、异步调度、事务和恢复。 | 将展示文案写死为业务规则。 |
| 基础适配 | 存储、网络、平台SDK、广告、支付、账号等。 | 让供应商接口渗透全部模块。 |
| 表现与主题 | 页面、组件、动效、音效、布局、文案和皮肤。 | 自行决定业务成功或发奖。 |
| 配置与数据 | 关卡／内容、资源映射、功能开关和版本化结构。 | 混入密钥或不可追溯临时参数。 |

### 生产关键流程定义状态

• 异步请求使用明确的待机、执行中、成功、失败、取消状态；每个状态定义允许输入。重复点击、返回、超时和晚到回调不可产生重复奖励、重复提交或丢失进度。

• 用户操作的逻辑确认与表现动画解耦。可并行时不因动画阻塞下一步；确实必须等待时给出短而明确的反馈。快点、连点、切后台、窗口失焦和暂停恢复均纳入测试。

• 重要写入与奖励幂等：保存唯一操作标识、完成标记或事务状态。崩溃后重试不得多扣资源或重复领奖；不能仅靠按钮禁用防重复。

### 持久化与错误回退

存档标注结构版本，定义默认值、迁移、原子写入、损坏检测和备份恢复。更新前验证旧存档样例；无法迁移时明确提示并保留可恢复副本。离线和网络错误有可执行的重试、取消或本地回退策略，不用无限加载掩盖失败。

### 复用与可维护性

上表是职责分离参考，不强制五层目录；简单项目可以合并层或使用少量模块。模块按真实边界协作，避免过度抽象和跨模块直接改私有状态。新需求优先扩展配置和接口，不到处打补丁。跨引擎复用需重新评估运行时、生命周期、序列化、资源与平台绑定；“换图片即可复用”仅适用于接口已解耦、功能一致且经过测试的组件。

## 06 美术资产与界面实现契约

### 资产生产前确认规格

为每类资产确定参考效果、设计分辨率、逻辑尺寸与导出倍率、屏幕适配、色彩空间、压缩方式及内存预算。高分辨率不能靠放大低清图伪装；重要文字优先使用可本地化的真实字体，而非烘焙在背景里。

| 交付项 | 验收内容 |
| --- | --- |
| 层级与组合 | 背景、前景、遮挡层、主体、阴影、高光、粒子与UI分离；说明叠放顺序与混合方式。 |
| 几何与交互 | 逻辑尺寸、透明边距、锚点、九宫格切片、热区、安全区、对齐与缩放规则。 |
| 组件状态 | 默认、按下、选中、禁用、加载、空态、错误、锁定／解锁及开／关状态按需要齐全。 |
| 身份与文件 | 统一命名、唯一资源ID、用途、版本、源文件、导出文件、图集映射、授权来源。 |
| 字体与本地化 | 字体许可和字形覆盖；长文案、数字居中、多语言换行；文本与图片可独立替换。 |
| 动作与反馈 | 帧率／时长、关键帧、事件点、循环／退出、运动曲线、遮挡、音效与触觉触发条件。 |

### 按可集成批次交付

先交付背景与主布局、基础组件、关键实体，再补完整状态和动效。每批附预览、清单、切图／模型文件、使用说明及验收截图；明确缺项，不让实现方猜测。透明图片检查白边、黑边和裁切；动画检查枢轴跳动、循环接缝与可中断状态。

### 还原标准与职责

实现人员按批准视觉基线还原；真机发现热区、文字、遮挡或性能问题时提出变更，经批准后更新基线，不为像素一致牺牲可用性。资源缺失先登记并用明确占位，不悄悄改设计。界面验收同时比较参考图与实际程序，检查视觉差异、按钮事件、热区和可读性，不能只看静态截图。

### 页面与状态漏项检查

按项目需要列出首页、主场景、设置、暂停、帮助、结果、失败、确认、权限、无网络、加载、空数据、错误、更新和退出等状态。广告／支付／排行榜／体力只在项目确实采用时加入；每个入口都必须有可返回的路径。

### 资产需求短模板

用途→主体与数量→风格／配色／材质→构图／视角／可见部件→结构与运动拆分→禁止项→输出规格→验收。先说明交付是概念图、建模参考还是可用模型／分层资产；PNG不等于可拆可动模型，纯净背景不等于透明背景。

## 07 分层测试与体验验收

| 测试层 | 证据与目标 | 不能替代 |
| --- | --- | --- |
| 静态与单元 | 格式／类型检查、规则边界、数据有效性、状态转换测试。 | 真实界面可操作。 |
| 集成与服务 | 接口契约、存档迁移、异步、幂等、错误和恢复测试。 | 线上供应商真实联调。 |
| 真实 GUI | 实际构建中点击、输入、返回、全流程截图与视频。 | 目标设备性能和真人理解。 |
| 目标设备 | 不同分辨率／比例、输入、性能、后台恢复、安装升级。 | 未测试设备的兼容性保证。 |
| 真人体验 | 记录用户背景、任务、观察、困惑、完成情况和反馈。 | 市场留存与商业结果。 |

### 测试执行规则

• 优先使用可用的MCP、自动化或测试框架，但先核实工具能否访问目标程序、点击控件、截图和读取结果。工具不可用时记录限制与替代方案，不声称完成未执行的测试。

• 独立QA从候选构建开始操作，而不是只读实现说明。先走正常主路径，再测快速连点、乱序输入、取消、重启、断网、重复回调、边界数值和旧存档。

• 真实程序截图／视频记录构建版本、设备、分辨率、步骤和实际结果。保留原始清晰素材；合成效果图、设计稿和放大截图必须标明，不能作为运行证据。

### 缺陷分级与放行

阻断：无法启动、主流程无法完成、数据丢失或严重安全问题；严重：核心功能错误、关键按钮无效或主要设备不可用；一般：有替代路径的功能／视觉问题；轻微：不影响理解和操作的细节。发布前阻断与严重缺陷清零，一般问题须说明影响和接受人。

### 体验问题不是只看技术正确

游戏同时观察首局理解、选择是否有意义、挫败是否可解释、爽感与动画等待时间；工具类观察任务效率、错误恢复和认知负担。试玩前写明对象、问题和观察任务；首体验尽量不解释，记录求助、退出、重试和理解偏差。修改后复测同一问题，不把“新手／熟练”当智力标签。人工样本不足时明确标注，不让自动脚本扮演真实用户评价。

每次修复必须复现原缺陷、验证修复，并回归相邻流程。一次通过只覆盖所记录的版本和条件。

## 08 可复用代码仓库建设计划

本节规定后续如何建立和采用共享仓库，不代表仓库已经建成。先在项目内验证，再因真实复用需求提取组件；不先建万能框架，不为抽象延迟核心验证。仓库可采用模块目录或独立包，按引擎与平台划分适配层。

| 阶段 | 准入与交付 |
| --- | --- |
| 候选登记 | 列出现有组件、使用项目、依赖、已知缺陷及维护人；默认未认证。 |
| 审计清理 | 检查授权、安全、耦合、测试和平台限制；删除项目专有数据、密钥与无权分发内容。 |
| 接口解耦 | 分离核心逻辑、主题／文案和SDK适配器；说明配置、输入输出与生命周期。 |
| 最小示例与回归 | 提供独立可运行示例、测试、错误／离线演示和接入说明；不依赖原项目才能跑。 |
| 稳定发布 | 标注语义版本、变更记录、兼容范围和迁移说明；通过审查后才标为稳定。 |
| 项目采用 | 锁定版本或提交，登记依赖；升级先跑兼容回归，保留回退版本。 |

### 模块登记最小字段

模块ID、用途、成熟度（候选／试验／稳定／弃用）、负责人、版本、许可证、引擎与运行时版本范围、平台、第三方依赖、配置、接口、示例、测试证据、限制和替代方案。禁止引用浮动最新版而不记录实际版本。

### 可选模块与适配边界

设置、语言切换、通用弹窗、暂停、结算、本机成绩、体力、广告、账号与排行榜都可作为候选，但不能默认新项目全部需要。UI皮肤与业务逻辑分离；不同平台的广告／支付、云服务或存储分别实现适配器。

本机成绩不是全球排行榜；模拟广告不是已接广告SDK；本地倒计时不等于安全的服务端经济系统。Stub／Mock必须在配置、页面及验收报告中明确标注。真实服务还需鉴权、异常、频率限制、隐私、作弊风险和上线验证。

### 回流规则

项目修复先在项目验证，再以独立变更回流共享库，补测试与版本说明。共享库升级不得静默改变其他项目；重大不兼容变更有迁移计划。只上传明确有权共享的代码与素材，访问权限按项目需要设置。

## 09 发布安全与交接完成定义

### 发布前的配置与合规检查

• 从立项识别签名所有权与安全备份，指定保管人和恢复验证；分离开发、测试和生产配置；密钥采用安全配置途径，不写入仓库、客户端可读文件、截图或日志。检查提交历史及交付包，发现泄漏按撤销／轮换流程处理，不只删除当前文件。

• 按目标市场和平台当期官方要求核对权限、隐私披露、数据处理、SDK、签名、年龄分级、广告／支付及账号删除等适用项，保存来源与核对日期。不把固定年份的政策数字当永久标准。

• 确认代码、图片、字体、音频、模型与第三方依赖许可证及商业使用范围。项目发布、付费服务、权限扩大等操作遵循授权要求，不因“开发完成”自动获得发布许可。

### 完成状态必须分别报告

| 状态 | 证明条件 |
| --- | --- |
| 已编写 | 文件存在且变更可定位，不代表可运行。 |
| 已测试 | 列出版本、环境、测试范围与结果；未测部分单列。 |
| 已提交／已推送 | 分别提供本地提交标识与远程分支／提交链接；不能混称。 |
| 已部署／设备已运行 | 分别给出部署目标与实际目标设备启动、操作证据。 |
| 已发布 | 核实发布渠道和实际可见状态；审核中、上传中不算发布。 |

### 交接包最小内容

README与启动／构建命令；实际引擎、运行时、工具及依赖版本；所用环境与模型记录；需求基线、架构和接口；源文件与许可证；构建产物和配置示例；测试日志与截图／视频；分支和提交；已知缺陷、风险、阻塞、下一步及维护人。禁止附带生产凭据。

### 独立接手验证

接手方从文档指定版本在目标环境执行安装、构建、启动和一条核心流程。无法复现时交接未通过；修正文档或依赖后再验收。至少保留上一可用构建、配置与必要备份；数据迁移不具备回滚能力时单独说明恢复路径。

项目结束以约定交付范围完成为准，不用“所有可能功能都做完”作为目标。未完成项可延期，但必须有人负责、有明确状态，不从清单中消失。

## 11 跨 AI 开工核验

首次进入项目做完整开工核验；续接或更换模型只核验基线以来的变化、未决风险和当前环境，不重复整套表单。规范仓库是入口，不是自动执行保证；项目负责人通过开工核验报告确认它确实被读取并正确应用。不得假设某种AI必定会自动读取AGENTS.md。

### 首次核验与续接差异检查

• 读取README入口、固定版本的规范正文、适用的可选流程、项目玩法／产品文档与当前交接记录。报告规范版本及commit、项目分支与commit；没有版本信息时写明未固定，不猜测。

• 检查实际代码、资产、构建、测试和缺陷状态。按证据区分已写、已测试、已推送、已运行与已发布，不从旧聊天恢复虚假的完成状态。

• 检查目标平台、引擎、依赖、账号权限、工具连接与环境。用户说某台电脑装了工具，不代表当前环境可调用；执行最小只读连通性检查，不擅自创建凭据或扩大权限。

• 逐项判断流程适用性：产品验证、视觉、2D／3D资产、在线服务、隐私与发布等。适用项列证据和待办；不适用项写N/A与理由。缺项明确负责人、阻塞关系和下一步。

• 输出首个可验证里程碑、文件归属、测试方法和需要用户决定的事项。核心输入或访问失败时停下依赖工作；无关且已授权的任务可以继续。

### GitHub 入口与版本管理

README作为人工与工具共同入口；AGENTS.md提供简短导航；其他工具的规则文件只指向同一规范，不复制正文。开工报告必须有读取位置、固定版本及适用性核验，不能只回答“已遵循”。工具约定不能绕过系统指令、权限与安全要求。环境重大改变需重做受影响的完整核验。

每个项目记录采用的规范版本与commit，不长期追随浮动latest。规范更新经过审阅，项目确认影响后再升级。私有仓库无权读取、链接失效或下载不全时，明确报告阻塞，不假装看过；由负责人提供授权访问或完整导出文件。

规范仓库：https://github.com/yxstart666/project-development-standard。采用时复制或引用已发布的指定版本，并记录实际commit；V1.1已发布commit为4efd5d756a5f47ca61690c818d64cbd0ad9d148f；采用时从 GitHub 提交记录取得实际 commit SHA，并在项目接入记录中固定。

### 可选 3D 流程的准入

先判断2D、3D或2.5D中是否实际需要3D模型。无需3D则记录N/A和理由；需要时进入附录流程，核验工具、预算、格式与目标环境，先用一个代表模型验证整条链路，再决定批量。安装了Hyper3D MCP不等于已授权付费生成。
